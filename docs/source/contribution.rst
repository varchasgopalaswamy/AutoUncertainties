CI and Unit Testing
-------------------

Development requires Python 3.15 or newer and uses ``uv`` for dependency management.
Woodpecker runs tests from the ``tests`` directory when commits are pushed to
Codeberg. Install the locked development tools and run the tests with:

.. code-block:: bash

   uv sync --locked --group ci
   uv run --locked --group ci pytest --cov --cov-report=term

Run the lint, formatting, static type, and generated-export checks before submitting
changes:

.. code-block:: bash

   uv run --locked --group ci ruff check .
   uv run --locked --group ci ruff format --check .
   uv run --locked --group ci pyrefly check
   uv run --locked --group ci geninit --check

The ``ci`` dependency group defines the minimum tool versions, and ``uv.lock``
records the versions shared by local checks, pre-commit hooks, and CI. Run
``scripts/ci/test.sh`` to execute the complete check sequence with coverage reports.
Pyrefly reads its project scope and Python version from ``pyrefly.toml`` and
discovers the local virtual environment interpreter automatically.

Package exports
---------------

Each module's ``__all__`` declares its public API. In the handwritten part of each
package's ``__init__.py``, ``__flattened__`` selects children whose public symbols
are re-exported without exposing their module names, and ``__private__`` excludes
implementation modules. NumPy dispatch is internal and exports no public symbols.

Use ordinary names for internal modules, helpers, and attributes; do not add an
underscore prefix to mark them private. Export declarations define the package
API. Keep prescribed protocol names, such as ``__init__`` and IPython's
``_repr_html_``, and names provided by dependencies unchanged.

Package initializers are generated by ``geninit`` using Python 3.15 native lazy
imports. Edit these declarations and regenerate instead of editing generated code:

.. code-block:: bash

   uv run --locked --group ci geninit
   uv run --locked --group ci geninit --check

Generation exits with status 2 when it updates files so that pre-commit can flag
the changes for review. A subsequent ``--check`` succeeds when the generated
files are current.


Documentation
-------------

To build the documentation locally, clone the repository, create a virtual Python environment 
(if desired), and run the following commands within the repository directory:

.. code:: bash

   pip install -e .[docs]
   sphinx-build docs/source docs/build
